# 外部ログイン対応: ブログ・writersの改修点

GitHub／Googleでログインした人（外部ユーザー）が、ブログの記事にコメントできるようにするための改修点です。

commonsのAPI仕様は次のファイルを正本とし、ここには改修の要点だけを書きます。

- 外部ログイン: `/documents/api/auth.md`
- トークンの確認: `/documents/api/tokens.md`

## 進める順番

1. commons: 本番に反映する（`AUTH_REDIRECT_ALLOWLIST`は空のまま）
2. writers: コメント投稿を外部ユーザーに対応させる
3. ブログ: ログインとコメント投稿の画面を作る
4. 公開: 本番の`AUTH_REDIRECT_ALLOWLIST`に戻り先ページのURLを設定し、Googleの同意画面を「本番」にする

## 全体の流れ

1. ブログ → commons: ログインを開始する
2. commons → GitHub／Google → commons: 認証する
3. commons → ブログの戻り先ページ: 一時コードを渡す（60秒・1回限り）
4. ブログ → commons: 一時コードをトークンに交換する（トークンは10分で失効、延長なし）
5. ブログ → writers: トークンを付けてコメントを投稿する
6. writers → commons: トークンを確認し、コメントを保存する

## writersの改修点

### コメントの投稿

- [ ] commonsの`POST /tokens/valid`に`allow_external: true`を付けて確認する
  - JSONの真偽値で送る（`"true"`や`1`は無効）
  - **コメントの投稿以外では付けない**（付けると、外部ユーザーに記事の編集などを許可してしまう）
- [ ] `valid`が`NG`なら`401`を返す
- [ ] 投稿者の情報は、ブログから送られた値ではなく、commonsの応答を使う
- [ ] 投稿時点の`user_id`・`provider`・`display_name`・`avatar_url`をコメントと一緒に保存する

保存する列の目安です。

| 項目 | 長さ | 注意 |
| --- | --- | --- |
| `user_id` | 32 | 外部ユーザーは`gh-`または`gg-`で始まる |
| `provider` | 16 | `github`／`google`。パスワードユーザーでは応答に含まれない |
| `display_name` | 255 | 絵文字を含むことがある（`utf8mb4`）。空のこともある。パスワードユーザーでは応答に含まれない |
| `avatar_url` | 2048 | 空のこともある。パスワードユーザーでは応答に含まれない |

### コメントの一括削除

- [ ] `user_id`を指定して、そのユーザーのコメントをすべて削除できるようにする（管理者のみ）
- 荒らしへの対応は、commonsの停止用CLI → writersの一括削除の順に行う（先に止めないと、削除後にまた投稿される）

### CORSと既存機能の確認

- [ ] ブログのオリジンをwritersのCORSで許可する（未設定の場合）
- [ ] 記事の編集など、既存の操作が外部ユーザーのトークンで拒否されることを確認する

## ブログの改修点

複数のブログで使う場合は、それぞれに必要です。

### ログインの開始

- [ ] `code_verifier`（乱数）を作り、`sessionStorage`に保存する
- [ ] 現在の記事のURLと、書きかけのコメントも`sessionStorage`に保存する
- [ ] commonsの`GET /auth/{provider}/login`へ画面遷移する（`fetch`では呼ばない）

```js
const base64Url = (bytes) =>
  btoa(String.fromCharCode(...bytes))
    .replace(/\+/g, '-').replace(/\//g, '_').replace(/=+$/, '');

async function startLogin(provider) {
  const verifier = base64Url(crypto.getRandomValues(new Uint8Array(32)));
  const hash = await crypto.subtle.digest('SHA-256', new TextEncoder().encode(verifier));
  const challenge = base64Url(new Uint8Array(hash));

  sessionStorage.setItem('code_verifier', verifier);
  sessionStorage.setItem('return_to', location.pathname + location.search);

  const query = new URLSearchParams({
    redirect_uri: REDIRECT_URI, // commonsの許可リストと完全に同じ文字列
    code_challenge: challenge,
  });
  location.href = `${COMMONS_URL}/auth/${provider}/login?${query}`;
}
```

- `crypto.subtle`はHTTPSか`localhost`でしか使えない

### 戻り先ページ（例: `/auth/callback`）

- [ ] URLを直接開いても404にならないようにする
- [ ] `code`を受け取ったら、`history.replaceState`でURLから取り除く
- [ ] `POST /auth/exchange`に`code`と`code_verifier`を送り、トークンを受け取る
- [ ] `code_verifier`を`sessionStorage`から削除し、元の記事へ戻ってコメントを復元する
- [ ] 失敗した場合（下の表）の表示を用意する

| 状況 | 意味 | 表示の例 |
| --- | --- | --- |
| `?error=access_denied` | 認可画面で拒否した | ログインがキャンセルされました |
| `?error=suspended` | 停止中のユーザー | このアカウントではコメントできません |
| `?error=provider_error` | GitHub／Googleとの通信に失敗 | 時間をおいてやり直してください |
| `exchange`が`401` | 一時コードの期限切れ・使用済みなど | もう一度ログインしてください |

- 一時コードは1回しか使えない。Reactの開発モード（StrictMode）では`useEffect`が2回動くので、`exchange`が1回だけ呼ばれるようにする
- 認可画面で5分以上経つと、ブログへは戻らずcommonsがエラー（JSON）を表示する

### コメント欄

- [ ] ログイン済みなら表示名とアバターを表示する（空の場合の代わりの表示も用意する）
- [ ] トークンを付けてwritersに投稿する
- [ ] `401`が返ったら（トークンの期限切れなど）、書きかけのコメントを残したまま再ログインできるようにする
- [ ] 表示名とコメントはHTMLとして表示しない（`dangerouslySetInnerHTML`を使わない）

### プライバシーポリシー

- [ ] プライバシーポリシーに追記する
  - 取得する情報: GitHub／GoogleのユーザーID、表示名、アバターのURL
  - 取得しない情報: メールアドレス
  - 利用目的: コメントの投稿者の識別と表示

## 決めること

- [ ] 外部ユーザーが自分のコメントを編集・削除できるようにするか
- [ ] パスワードユーザーがコメントする場合の表示名（commonsは`user_id`しか返さない）
- [ ] コメントをすぐに公開するか、承認してから公開するか
- [ ] 連続投稿を制限するか
- [ ] 投稿者のアバターを表示するか（表示すると、閲覧者のブラウザがGitHub／Googleの画像に接続する）
